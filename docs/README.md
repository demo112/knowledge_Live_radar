## 🚀 快速开始

### 新成员入职

1. **第一天**：阅读 [核心哲学](./core-philosophy.md)，理解项目本质
2. **第二天**：阅读 [需求文档](./requirements.md) 和 [需求分析](./requirement-analysis.md)
3. **第三天**：阅读 [AI-First缺失分析](./analysis/ai-first-gap-analysis.md)，了解当前问题
4. **第四天**：阅读 [项目认知重新分析](./analysis/project-cognition-reanalysis.md)，了解整改方向
5. **第五天**：阅读技术文档，开始编码

### 开发新功能

在开发任何新功能前，必须：

1. ✅ 确认功能符合 [核心哲学](./core-philosophy.md) 中的原则
2. ✅ 检查是否涉及"信息加工"（如果是，必须有AI参与）
3. ✅ 设计AI如何参与（理解、分析、生成、评估）
4. ✅ 设计用户如何看到AI的工作
5. ✅ 设计用户如何修正AI的理解
6. ✅ 在设计文档中说明AI参与方式

### 代码审查

审查任何PR时，必须检查：

- [ ] 是否符合AI-First原则？
- [ ] 涉及信息加工的操作是否有AI参与？
- [ ] 用户能看到AI的工作吗？
- [ ] AI的推理过程被记录了吗？
- [ ] 有降级方案吗？
- [ ] 是否有反模式？（参考 [核心哲学](./core-philosophy.md) 第六章）

## 🎓 核心概念速查

### 三大第一性原则

1. **AI-First（AI优先）**
   - 所有信息加工都经过AI
   - 判断标准：涉及"理解"、"分析"、"判断"、"生成"就必须有AI

2. **Human-in-the-Loop（人类在环）**
   - AI建议，人类决策
   - 交互模式：输入 → AI理解 → 生成建议 → 用户确认 → 执行

3. **Evolution-Driven（进化驱动）**
   - 系统持续进化
   - 进化循环：感知 → 认知 → 评估 → 建议 → 决策 → 执行 → 反馈

### 五大核心价值观

1. 智能优先于手动
2. 即时反馈优于异步处理
3. 透明优于黑盒
4. 质量优于数量
5. 协作优于自动化

### 四大反模式（禁止）

1. ❌ AI作为可选功能
2. ❌ 后台异步AI处理
3. ❌ AI黑盒决策
4. ❌ 忽略用户反馈

## 💡 常见问题

### Q1: 为什么要强调AI-First？

**A**: 因为AI Radar的本质是"AI驱动的认知系统"，而不是"传统系统+AI增强"。如果AI不是核心，系统就失去了存在的意义。

### Q2: 所有操作都必须有AI参与吗？

**A**: 不是。只有涉及"信息加工"的操作才需要AI。纯粹的CRUD操作（如删除、查询）不需要AI。

### Q3: AI处理太慢怎么办？

**A**: 
1. 设置5秒超时
2. 使用流式响应
3. 实现智能缓存
4. 提供降级方案

### Q4: 用户不信任AI怎么办？

**A**:
1. 透明展示AI推理过程
2. 显示置信度和备选方案
3. 允许用户修改
4. 记录并展示AI准确率

### Q5: 如何判断一个操作是否涉及"信息加工"？

**A**: 问自己三个问题：
1. 这个操作需要"理解"用户输入吗？
2. 这个操作需要"分析"或"判断"吗？
3. 这个操作需要"生成"建议吗？

如果任何一个答案是"是"，就涉及信息加工，必须有AI参与。
