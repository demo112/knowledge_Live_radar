## 描述

用户反馈 "Discover New Sources" 的结果完全不符合需求。
主要问题：
1. 关键词太泛（如 "辅助工具"）。
2. 搜索结果包含大量非目标站点（如百度经验、知乎问答、CSDN等），而用户通常期望高质量的独立博客或技术专栏。
3. 搜索 Query 简单（`{keyword} 博客 RSS`），容易搜出 SEO 垃圾。

## 根因分析

1. **关键词提取逻辑简单**：仅使用 `PyramidNode.name`，缺乏上下文。例如节点名为 "辅助工具"，在 "王者荣耀" 目录下，但搜索时丢失了父节点信息，导致搜出通用的 "辅助工具"（如 Windows 辅助功能）。
2. **搜索 Query 优化不足**：DuckDuckGo 搜索时没有排除常见的内容农场或非目标站点。

## 解决方案

1. **增强关键词上下文**：
   - 修改 `_get_keywords` 方法，获取节点的父节点信息。
   - 如果存在父节点，将关键词组合为 `"{Parent Name} {Node Name}"`（如 "王者荣耀 辅助工具"）。
   - 避免重复（如父节点名已包含在子节点名中则不组合）。

2. **优化搜索 Query**：
   - 将 Query 从 `"{keyword} 博客 RSS"` 改为 `"{keyword} (技术博客 OR 专栏 OR 官方文档)"`。
   - 虽然移除了显式的 `RSS` 关键词（因为很多现代博客 RSS 隐藏较深，先找到主页再探测 RSS 更有效），但目前 MVP 阶段主要依赖 DDG 结果。
   - 代码注释中保留了未来优化方向（如 `site:` 过滤）。

3. **结果过滤**：
   - 在代码中增加了对 `baidu.com` 和 `google.com` 等非内容页的过滤。
