# AI Radar 核心哲学与价值观

> **本文档是项目的哲学基础，所有设计决策、技术选型、功能实现都必须符合这里定义的核心价值观。**

---

## 一、项目本质定义

### 1.1 我们是什么

**AI Radar 是一个AI驱动的认知系统，而不是一个传统的知识管理工具。**

```
错误理解：知识管理系统 + AI增强功能
正确理解：AI认知系统 + 人类决策 + 知识存储
```

**类比**：
- 不是"图书馆 + 智能检索"
- 而是"会思考的图书管理员 + 人类馆长"

### 1.2 我们不是什么

我们不是：
- ❌ 静态的知识库（如Wikipedia）
- ❌ 简单的信息聚合器（如RSS阅读器）
- ❌ 传统的CMS系统（如WordPress）
- ❌ 纯人工管理的知识平台

我们是：
- ✅ 会自我进化的智能系统
- ✅ 理解知识结构的认知体
- ✅ 人机协作的决策平台

## 二、第一性原理

### 原则1：AI-First（AI优先）

**定义**：凡是涉及"信息加工"的操作都必须经过AI处理。

**信息加工包括但不限于**：
- 理解用户输入的语义
- 从非结构化文本中提取结构化信息
- 分析内容并生成分类建议
- 评估变更的影响
- 生成优化建议
- 发现知识缺口

**实践要求**：
```python
# ❌ 错误：直接保存用户输入
def create_pyramid(name, description):
    return db.save({"name": name, "description": description})

# ✅ 正确：AI先理解，再保存
def create_pyramid(name, description):
    understanding = ai.understand(description)
    structure = ai.generate_structure(understanding)
    return {"suggestion": structure, "understanding": understanding}
```

**判断标准**：
- 如果一个操作涉及"理解"、"分析"、"判断"、"生成"，就必须有AI参与
- 如果用户期望系统"懂"他的意图，就必须有AI参与
- 如果操作结果会影响知识结构，就必须有AI参与

### 原则2：Human-in-the-Loop（人类在环）

**定义**：AI负责理解和建议，人类负责确认和决策。

**协作模式**：
```
用户输入 → AI理解 → AI生成建议 → 展示给用户 → 用户确认/修改 → 执行
```

**而不是**：
```
用户输入 → 直接保存 → 后台AI处理 → 用户看不到
```

**实践要求**：
- 所有AI建议都必须展示给用户
- 用户必须能够修改AI的建议
- 重要决策必须经过人类确认
- AI的推理过程必须透明可见

**权限分配**：
| 操作类型 | AI职责 | 人类职责 |
|---------|--------|---------|
| 理解输入 | ✅ 主导 | ❌ 不参与 |
| 生成建议 | ✅ 主导 | ❌ 不参与 |
| 评估影响 | ✅ 主导 | ⚠️ 审查 |
| 结构变更 | ❌ 不执行 | ✅ 决策 |
| 方向把控 | ❌ 不参与 | ✅ 主导 |

### 原则3：Evolution-Driven（进化驱动）

**定义**：系统是一个持续进化的有机体，而不是静态的数据库。

**进化的三个层次**：

1. **内容进化**：新内容不断加入，旧内容被淘汰
2. **结构进化**：知识金字塔随领域发展而调整
3. **系统进化**：抓取策略、分类算法、AI能力持续优化

**进化循环**：
```
感知（抓取） → 认知（理解） → 评估（健康检测） → 
建议（生成提案） → 决策（人类审批） → 执行（变更） → 
反馈（效果评估） → 感知（继续抓取）
```

**实践要求**：
- 系统必须主动发现问题（不等人类发现）
- 系统必须主动生成优化建议
- 所有变更都必须记录和可追溯
- 系统必须从反馈中学习

## 三、核心价值观

### 价值观1：智能优先于手动

**含义**：能让AI做的，就不让人做。

**实践**：
- ❌ 让用户手动创建每个节点
- ✅ AI根据描述生成完整结构，用户只需确认

- ❌ 让用户手动分类每条内容
- ✅ AI自动分类，用户只需审核

**边界**：
- AI做"繁琐的"、"重复的"、"需要理解的"工作
- 人类做"决策性的"、"创造性的"、"把控方向的"工作

### 价值观2：即时反馈优于异步处理

**含义**：用户应该立即看到AI的工作结果，而不是等待。

**实践**：
- ❌ 用户提交内容 → 返回"已提交" → 后台处理
- ✅ 用户提交内容 → AI立即分析 → 返回分析结果

**技术要求**：
- AI处理必须在5秒内完成
- 如果超时，必须有降级方案
- 使用流式响应提升体验

### 价值观3：透明优于黑盒

**含义**：AI的推理过程必须可见、可理解、可追溯。

**实践**：
- 每个AI建议都必须附带推理过程
- 用户可以查看AI为什么这样建议
- 所有AI决策都有审计日志

**示例**：
```json
{
  "suggestion": "将此内容分类到'MCP协议'节点",
  "reasoning": "内容中提到了'Model Context Protocol'、'servers'、'clients'等关键词，与'MCP协议'节点的描述高度匹配",
  "confidence": 0.92,
  "alternative_suggestions": [
    {"node": "AI工具", "confidence": 0.65}
  ]
}
```

### 价值观4：质量优于数量

**含义**：宁可少而精，不要多而杂。

**实践**：
- 严格的三层校验机制
- 只采信权威一手源
- 宁缺毋滥的原则

**体现**：
- 信息源必须经过验证才能激活
- 内容必须通过校验才能入库
- 低质量内容会被自动淘汰

### 价值观5：协作优于自动化

**含义**：不追求完全自动化，而是追求最佳的人机协作。

**实践**：
- AI不会自动执行结构变更（需要人类确认）
- AI不会自动删除内容（需要人类审批）
- AI不会自动调整重要配置（需要人类决策）

**理由**：
- 知识结构是主观的，需要人类把控方向
- 完全自动化可能导致不可控的演化
- 人类的判断在关键决策中不可替代

## 四、系统能力模型（修正版）

### 4.1 架构层次

```
┌─────────────────────────────────────────────────────────────┐
│                    人类决策层 (Human Layer)                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  审批变更    │  │  把控方向    │  │  制定规则    │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└────────────────────────┬────────────────────────────────────┘
                         │ (所有重要决策)
┌────────────────────────┴────────────────────────────────────┐
│                    AI认知层 (AI Core) ★核心★                │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  理解  │  分析  │  生成  │  评估  │  建议  │  学习  │  │
│  └──────────────────────────────────────────────────────┘  │
│  所有信息加工都在这里完成                                   │
└────────────────────────┬────────────────────────────────────┘
                         │ (结构化数据)
┌────────────────────────┴────────────────────────────────────┐
│                    执行层 (Execution Layer)                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  数据存储    │  │  任务调度    │  │  通知推送    │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└─────────────────────────────────────────────────────────────┘
```

**关键点**：
1. AI认知层是核心，所有信息加工都经过这里
2. 人类决策层在上，把控方向
3. 执行层在下，负责存储和调度

### 4.2 信息流向

```
外部信息 → 感知层(抓取) → AI认知层(理解/分析) → 人类决策层(确认) → 执行层(保存)
                                    ↓
                              生成建议/提案
                                    ↓
                              展示给用户
```

**不是**：
```
外部信息 → 直接保存 → 后台AI处理
```

## 五、设计原则

### 原则1：AI能力必须前置

**含义**：在设计任何功能时，首先考虑AI如何参与。

**检查清单**：
- [ ] 这个功能涉及信息加工吗？
- [ ] AI如何理解用户输入？
- [ ] AI如何生成建议？
- [ ] 用户如何看到AI的工作？
- [ ] 用户如何修正AI的理解？

### 原则2：两阶段交互模式

**含义**：涉及AI的操作应该分为"建议"和"确认"两个阶段。

**API设计**：
```
POST /resource/suggest  # 阶段1：获取AI建议
POST /resource/confirm  # 阶段2：确认并执行
```

**而不是**：
```
POST /resource  # 一步完成（用户看不到AI做了什么）
```

### 原则3：记录AI推理过程

**含义**：所有AI的决策都必须记录推理过程。

**数据模型要求**：
```python
class AISuggestion(Base):
    input_data: dict       # 输入
    ai_output: dict        # 输出
    reasoning: str         # 推理过程 ← 必需
    confidence: float      # 置信度 ← 必需
    alternatives: list     # 备选方案 ← 必需
```

### 原则4：降级方案必须存在

**含义**：AI失败时，系统必须能够降级运行。

**实践**：
- AI超时 → 跳过AI，使用规则
- AI质量低 → 人工介入
- AI不可用 → 纯手动模式

## 六、反模式（禁止的做法）

### 反模式1：AI作为可选功能

❌ **错误**：
```python
def create_pyramid(data, use_ai=False):  # AI是可选的
    if use_ai:
        # AI处理
    else:
        # 直接保存
```

✅ **正确**：
```python
def create_pyramid(data):
    # AI处理是必需的
    understanding = ai.understand(data)
    suggestion = ai.generate(understanding)
    return suggestion
```

### 反模式2：后台异步AI处理

❌ **错误**：
```python
def submit_content(data):
    content = save_to_db(data)
    background_task.add(ai_process, content.id)  # 后台处理
    return {"status": "submitted"}  # 用户看不到AI结果
```

✅ **正确**：
```python
def submit_content(data):
    ai_result = ai.process(data)  # 立即处理
    content = save_to_db(data, ai_result)
    return {
        "content": content,
        "ai_analysis": ai_result  # 用户立即看到
    }
```

### 反模式3：AI黑盒决策

❌ **错误**：
```python
def classify_content(content):
    node_id = ai.classify(content)  # 只返回结果
    return node_id
```

✅ **正确**：
```python
def classify_content(content):
    result = ai.classify(content)
    return {
        "node_id": result.node_id,
        "reasoning": result.reasoning,  # 推理过程
        "confidence": result.confidence,  # 置信度
        "alternatives": result.alternatives  # 备选方案
    }
```

### 反模式4：忽略用户反馈

❌ **错误**：
```python
def apply_suggestion(suggestion_id):
    suggestion = get_suggestion(suggestion_id)
    execute(suggestion)  # 直接执行，不记录用户反馈
```

✅ **正确**：
```python
def apply_suggestion(suggestion_id, user_modifications):
    suggestion = get_suggestion(suggestion_id)
    # 记录用户反馈
    record_feedback(suggestion_id, user_modifications)
    # 执行（可能包含用户修改）
    execute(suggestion, user_modifications)
```

## 八、文化与团队

### 开发文化

1. **AI-First思维**：在设计任何功能时，首先问"AI如何参与？"
2. **用户中心**：所有决策都从用户体验出发
3. **透明优先**：代码、决策、AI推理都应该透明
4. **持续进化**：系统和团队都应该持续学习和改进

### 代码审查标准

每个PR必须回答：
- [ ] 这个功能涉及信息加工吗？
- [ ] 如果是，AI如何参与？
- [ ] 用户能看到AI的工作吗？
- [ ] AI的推理过程被记录了吗？
- [ ] 有降级方案吗？

### 设计评审标准

每个设计必须回答：
- [ ] 符合AI-First原则吗？
- [ ] 符合Human-in-the-Loop原则吗？
- [ ] 符合Evolution-Driven原则吗？
- [ ] 用户体验是否流畅？
- [ ] 是否有反模式？
