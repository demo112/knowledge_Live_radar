# Requirements: 知识金字塔核心管理增强

## Overview

增强知识金字塔系统的核心管理能力，重点解决现有系统中节点操作灵活性不足（缺乏拆分/合并）和健康度评估缺失的问题。本迭代将实现金字塔的全生命周期管理、高级节点操作以及基于健康度的可视化展示。

## User Stories

### Story 1: 金字塔全生命周期管理

As a 知识管理员, I want 创建、管理并监控金字塔的状态, so that 我可以系统化地维护 AI 知识体系

**Acceptance Criteria:**

- [ ] AC1: 创建金字塔（含模板）
  - **Given**: 管理员已登录
  - **When**: 管理员选择“从模板创建”，选择“AI 开发工具链”模板
  - **Then**: 系统创建新金字塔，自动生成预设的分类节点结构，返回新金字塔详情
  - **Note**: 支持模板：AI 开发工具链、Agent 生态、Prompt 工程、模型应用能力、热点追踪

- [ ] AC2: 金字塔列表带健康度
  - **Given**: 存在多个金字塔，部分有内容
  - **When**: 管理员查看金字塔列表
  - **Then**: 列表显示每个金字塔的名称、节点数、**健康度评分**（0-100）、最后更新时间

- [ ] AC3: 删除金字塔（归档）
  - **Given**: 金字塔中有节点和关联内容
  - **When**: 管理员执行删除操作
  - **Then**: 金字塔标记为 `is_deleted=True`（软删除），关联信息源解除绑定，返回成功

### Story 2: 高级节点管理（拆分与合并）

As a 知识管理员, I want 能够拆分和合并节点, so that 我可以随着知识领域的演变重构金字塔结构

**Acceptance Criteria:**

- [ ] AC1: 拆分节点
  - **Given**: 节点 A 下关联了 10 条内容
  - **When**: 管理员请求将节点 A 拆分为 A1, A2
  - **Then**: 
    - 创建子节点 A1, A2
    - 原节点 A 的内容根据（模拟的）AI 建议或默认规则分配给 A1 或 A2（首期可默认保留在 A 或手动分配）
    - 节点 A 变为容器节点（非叶子节点）

- [ ] AC2: 合并节点
  - **Given**: 兄弟节点 B1, B2 分别关联了内容
  - **When**: 管理员请求合并 B1, B2 为新节点 B
  - **Then**: 
    - 创建/更新节点 B
    - B1, B2 的所有子节点挂载到 B 下
    - B1, B2 的所有关联内容移动到 B
    - 删除 B1, B2

- [ ] AC3: 跨金字塔关联
  - **Given**: 金字塔 P1 的节点 N1，金字塔 P2 的节点 N2
  - **When**: 管理员建立 N1 -> N2 的关联
  - **Then**: 系统记录关联关系，查询 N1 详情时可看到关联的 N2

### Story 3: 金字塔健康度与可视化

As a 用户, I want 直观查看金字塔结构和健康状态, so that 我能快速发现知识体系的薄弱环节

**Acceptance Criteria:**

- [ ] AC1: 健康度计算模型
  - **Given**: 金字塔结构和内容更新记录
  - **When**: 系统触发健康度计算
  - **Then**: 
    - **深度平衡性**: 计算叶子节点深度的标准差，差异过大扣分
    - **节点覆盖度**: 检查空节点（无内容）和过载节点（内容>50），异常比例高扣分
    - **更新活跃度**: 计算近 30 天有更新的节点比例
    - 综合评分 = 权重加权和

- [ ] AC2: 可视化数据结构
  - **Given**: 请求金字塔可视化
  - **When**: 调用 API `/api/v1/pyramids/{id}/visualization`
  - **Then**: 返回 JSON 包含：
    - `nodes`: { id, label, level, health_score, content_count, last_updated }
    - `edges`: { source, target, type }

- [ ] AC3: 颜色编码
  - **Given**: 前端接收到可视化数据
  - **When**: 渲染金字塔
  - **Then**: 
    - 健康度 < 60 显示为红色警告
    - 健康度 60-80 显示为黄色注意
    - 健康度 > 80 显示为绿色健康

## Constraints

- **性能**: 健康度计算涉及全树遍历，需在写入时异步计算或缓存结果（首期可实时计算，节点数<1000）
- **数据一致性**: 拆分/合并操作必须在事务中执行

## Out of Scope

- AI 自动分类内容到拆分后的节点（本期仅提供接口，内容分配逻辑由人工或后续 AI 任务处理）
- 3D 可视化（本期仅支持 2D 树/图）

## Assumptions

- 拆分节点时，默认不自动迁移内容，需后续手动调整，或者全部挂载到父节点。
- 健康度计算暂时只需按需触发，不需要后台定时任务。
