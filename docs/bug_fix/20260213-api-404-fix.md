# API 404 错误修复记录

## 问题描述
- **现象**：
  - 点击"立即检测"报错：`Detection failed AxiosError: Request failed with status code 404` (URL: `/health/detection`)
  - 点击"优化抓取策略"报错：`Optimization failed AxiosError: Request failed with status code 404` (URL: `/evolution/optimize`)
- **复现步骤**：
  1. 进入系统健康页面 `/health`
  2. 点击"立即检测"或"优化抓取策略"按钮
  3. 观察 Console 报错
- **影响范围**：
  - 健康检测功能
  - 抓取策略优化功能

## 设计锚定
- **所属规格**：`pyramid-evolution` / `ai-radar-iteration-4`
- **原设计意图**：
  - 健康检测由 `HealthDetector` 提供，API 路径为 `/health/detect` (见 `backend/app/routers/health.py`)
  - 策略优化由 `StrategyAdapter` 提供，API 路径为 `/strategy/optimize` (见 `backend/app/routers/strategy.py`)
- **当前偏离**：
  - 前端 `api.ts` 中定义的路径与后端不一致

## 根因分析
- **直接原因**：前端请求的 API 路径在后端不存在。
- **根本原因**：前后端开发过程中 API 路径定义未对齐，或者后端重构后前端未同步更新。
- **相关代码**：`frontend/src/lib/api.ts`

## 修复方案
- **修复思路**：修正前端 `api.ts` 中的 API 路径，使其与后端保持一致。
- **改动文件**：
  - `frontend/src/lib/api.ts`

## 验证结果
- [x] 原问题已解决：后端接口已通过 curl 验证存在
  - `POST /api/v1/health/detect` -> 200 OK
  - `POST /api/v1/strategy/optimize` -> 200 OK
- [x] 回归测试通过：仅修改路径字符串，不影响其他逻辑
- [x] 设计一致性确认：符合后端路由设计
