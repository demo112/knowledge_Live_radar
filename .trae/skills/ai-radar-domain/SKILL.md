# AI Radar 业务领域知识

## 系统定位

AI Radar 是面向大模型应用领域的自进化知识聚合平台，核心能力：感知（信息抓取）、认知（内容理解）、进化（结构优化）。

## 核心数据模型

### Knowledge_Pyramid（知识金字塔）
- 层级化知识组织结构
- 每个金字塔代表一个知识领域
- 预设模板：AI 开发工具链、Agent 生态、Prompt 工程、模型应用能力、热点追踪
- 健康度指标：深度平衡性、节点覆盖度、更新活跃度

### Pyramid_Node（金字塔节点）
- 金字塔中的单个知识单元
- 父子层级关系
- 支持操作：添加、编辑、删除、移动、拆分、合并
- 支持跨金字塔关联

### Information_Source（信息源）
- 四种类型：RSS、API、网页爬取、用户贡献
- 生命周期：发现 → 验证 → 活跃 → 监测 → 调整 → 淘汰
- 健康指标：可达性、更新频率、内容质量、响应时间

### Content_Item（内容条目）
- 从信息源抓取或用户提交的单条信息
- 包含：原文URL、摘要、标签、校验状态、分类
- 三层校验：硬性规则 + AI 软性 + 多源交叉

### Change_Proposal（变更提案）
- AI 生成的变更建议
- 类型：金字塔结构变更、信息源变更、策略变更
- 必须经过人类审批

### Hotspot（热点话题）
- 生命周期：新兴 → 热门 → 成熟 → 冷却 → 归档

## 核心业务流程

### 信息抓取流程
```
定时触发 → 创建抓取任务 → 执行抓取 → 去重检查 → 创建 Content_Item → 提交校验
```

### 三层校验流程
```
硬性校验（URL可达、域名白名单、格式验证）
    ↓ 通过
软性校验（AI评估：信息密度、原创性、一致性、广告检测、时效性）
    ↓ 通过
交叉验证（多源确认、冲突检测）
    ↓ 完成
内容分类 → 生成摘要 → 推荐节点 → 入库
```

### 审批流程
```
AI 生成 Change_Proposal → 加入审批队列 → 计算优先级
    → 管理员审批（批准/拒绝/修改）→ 执行变更 → 记录历史
```

### 进化循环
```
感知 → 理解 → 评估 → 建议 → 审批 → 执行 → 反馈 → 感知
```

## 信息可信度模型

```
可信度 = f(来源权威性, 校验通过率, 多源确认度, 时效性)

来源权威性：官方 > 学术 > 权威媒体 > 社区 > 个人
```

## 关键业务规则

1. 所有结构性变更必须经过人类审批
2. 信息源必须遵守 robots.txt
3. 同一域名限制请求频率
4. 宁缺毋滥：宁可漏掉信息，不可传播不实内容
5. AI 建议必须有清晰的推理过程和依据
6. 每条信息的完整校验链路对用户透明可查
