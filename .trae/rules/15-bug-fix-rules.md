# Bug 修复规范

## 核心原则

> **设计锚定 + 最小改动 + 回归验证**

---

## 修复前：设计锚定

修复任何问题前，必须先读取原设计文档，回答：
1. 原设计是什么？
2. 当前代码哪里偏离了设计？
3. 修复方案是否符合原设计？

## 修复中：范围控制

| 允许 | 禁止 |
|------|------|
| 修复逻辑错误 | 顺便重构 |
| 修复边界条件 | 顺便优化 |
| 补充缺失校验 | 增加新功能 |

### 改动范围预警

| 触发条件 | 处理 |
|----------|------|
| > 3 个文件 | 暂停确认 |
| 涉及校验/审批/抓取核心逻辑 | 暂停确认 |
| 涉及 SQLAlchemy 模型 | 暂停确认 |
| 涉及 AI Prompt 模板 | 暂停确认 |

## 修复后：回归验证

- [ ] 原问题已解决（有证据）
- [ ] pytest / npm test 通过
- [ ] 代码与 design.md 一致
- [ ] 没有引入新行为
- [ ] 如有模型变更：Alembic 迁移已生成

## 文档输出

每次修复在 `docs/issues/{YYYYMMDD}-{问题简述}-fix.md` 创建记录。

## Git 同步

- 修复前：`git pull --rebase origin main`
- 修复后验证通过才提交
- 一问题一提交
