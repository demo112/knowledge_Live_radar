# 受保护路径规则

## 禁止 AI 修改的路径

| 路径 | 说明 |
|------|------|
| `.trae/` | Trae 配置和规则文件 |
| `.kiro/` | Kiro 配置和 steering 文件 |
| `.env` | 环境变量配置文件 |
| `.env.local` | 本地环境变量配置文件 |

## docs 根目录系统级文档

`docs/` 根目录下的以下文档属于系统级约定文档：

- `api-contract.md` - API 契约
- `database-design.md` - 数据库设计
- `requirements.md` - 需求规格
- `requirement-analysis.md` - 需求分析
- `project-roadmap.md` - 项目路线图
- `task-backlog.md` - 任务清单
- `changelog.md` - 变更日志
- `deployment.md` - 部署文档

### 生命周期规则

这些文档遵循 **先建后锁** 的生命周期：

| 阶段 | 状态 | AI 行为 |
|------|------|---------|
| 项目初建期 | 🟢 **未创建** | AI **必须**协助创建这些文档，建立系统级约定 |
| 文档创建中 | 🟡 **草稿** | AI 可以编辑，直到用户确认内容完成 |
| 用户确认完成 | 🔴 **已锁定** | AI **禁止**直接修改，只能提供修改建议 |

### 锁定判断

- 文档**不存在** → 属于初建期，AI 应主动创建
- 文档**已存在** → 视为已锁定，AI 禁止修改

### 初建期行为

项目初建时，AI 应按以下顺序创建系统级文档：

1. `requirements.md` - 从需求规格出发
2. `requirement-analysis.md` - 需求分析
3. `database-design.md` - 数据库设计
4. `api-contract.md` - API 契约
5. `project-roadmap.md` - 项目路线图与迭代计划
6. `task-backlog.md` - 任务清单
7. `deployment.md` - 部署文档
8. `changelog.md` - 变更日志（初始版本）

创建完成后，这些文档自动进入锁定状态。

### 锁定后行为

```
这个文件位于受保护路径且已锁定，我无法直接修改。
建议修改内容如下：
[修改内容]
请您手动更新。
```

**注意**：`docs/features/` 和 `docs/progress/` 子目录下的文档不受此规则限制，可以正常编辑。

## 通用规则

1. 对于已锁定的文件，**禁止创建/修改/删除**
2. 如用户要求修改已锁定文件，**拒绝执行**并提供修改建议
3. 对于不存在的系统级文档，AI 应主动提醒并协助创建
